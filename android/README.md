# Android APK — build and run

Short notes for the Android target. The full project documentation, status,
roadmap and credits are in the [root README](../README.md).

## Status

**M2a — recompiled guest wired into the APK.** `libmain.so` now contains the
generated entrypoint code for `default.xex`, the ReXGlue `ReXApp` host, the
Xenos GPU plugin and the coroutine bridge:

```
MainActivity -> GameActivity (SDLActivity) -> libmain.so
  -> ReXApp -> Runtime -> KernelState -> recompiled default.xex
  -> rex::ui::Window + librexgpu-xenos.so -> VulkanPresenter
```

The 15 mission modules are not linked yet; only the entrypoint boots. On-device
boot is not verified: no Android device was attached while this build was made.
The launcher can pick a game folder or use `/sdcard/cod3`, verifies
`default.xex`, and adds a touch overlay on top of the SDL surface.

Logs go to two files in the app external files folder:

```
logfile.txt       # launcher and Java lines
native-log.txt    # ReXGlue runtime, Vulkan and guest lines
```

The split is deliberate: the SDK file sink opens its file with truncation, so
sharing one path with the Java appender corrupted both files.

The launcher footer shows the Java path; tap it to copy. `adb pull` both files
after testing. Native lines also appear in logcat under the `project1944` tag.

## Game data

The APK cannot read an ISO. Extract the disc image and put the contents
directly in the game folder:

```
/sdcard/cod3/default.xex
/sdcard/cod3/sp/...
```

`default.xex` must be in the folder root. This device has no
`OPEN_DOCUMENT_TREE` handler, so the system folder picker is unavailable: use
`USE /sdcard/cod3` and grant All-files access, otherwise the folder stays
invisible to the app.

## Build

The guest code is generated from the user's own disc and is not in the
repository. Generate it once, outside the checkout:

```powershell
$env:COD3_GENERATED_DIR = 'D:/cod3-gen/generated'
$rexglue = 'D:\tools\sdk\extract\win-amd64\bin\rexglue.exe'
& $rexglue codegen D:\cod3-gen\cod3_pc_manifest.toml --target blkbrn
# ... one --target run per mission module; the entrypoint is always included
```

Then build the APK with the same environment variable set:

```powershell
cd C:\Users\runneradmin\Downloads\cod3-android
.\android\patches\apply-sdk-patch.ps1   # fresh submodule only
.\android\scripts\build-debug.ps1
```

APK output:

```
android/app/build/outputs/apk/debug/app-debug.apk
```

Direct Gradle build:

```powershell
cd android
.\gradlew.bat :app:assembleDebug --console=plain
```

## Install and run

```powershell
.\android\scripts\doctor.ps1
.\android\scripts\install-debug.ps1
.\android\scripts\logcat.ps1
```

Manual:

```powershell
adb install -r android\app\build\outputs\apk\debug\app-debug.apk
adb shell am start -n com.project1944.cod3/.MainActivity
```

Expected: launcher UI with status chips and game-data card, then the guest boot
log, and logcat lines tagged `project1944` with the SDL video driver and the
selected Vulkan device.

Mobile GPUs omit optional Vulkan features that the desktop device selector
requires. The Android host clears `vulkan_require_vertex_pipeline_stores_and_atomics`,
`vulkan_require_geometry_shader` and `vulkan_require_fill_mode_non_solid` in
`OnPreSetup`. Without `vertexPipelineStoresAndAtomics`, vertex-stage memexport
draws are skipped and the GPU logs a warning instead of refusing the device.

## ReXGlue SDK patch

`tools/rexglue-source` stays at upstream pin
`0c7b01a0ac0479801757507d80533f662fa0815d`. All Android changes live in a patch:

```powershell
.\android\patches\apply-sdk-patch.ps1    # after a fresh submodule checkout
.\android\patches\export-sdk-patch.ps1   # after editing the SDK
```

Never commit the SDK submodule's modified working tree; commit the patch.

## Legal boundary

Never commit:

- `default.xex`, mission XEXs, ISOs, or extracted game data;
- generated/recompiled game C++;
- APKs or `.so` files containing game-derived code.

The app reads the user's own game folder in place. The APK is built locally and
is not distributed.
